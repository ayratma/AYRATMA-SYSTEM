# AYRATMA CORE local backend

A Termux-friendly local assistant backend with llama.cpp inference, SQLite notes and chat history, specialist role prompts, task records and approval records.

## One-command setup in Termux

From the repository root run:

    bash backend/start_termux.sh

The first run installs the Termux llama-cpp package and downloads Qwen2.5-1.5B-Instruct Q4_K_M (about 1.12 GB) into ~/.ayratma/models. It then starts llama-server on 127.0.0.1:8080 and the AYRATMA API on 127.0.0.1:8765. The download can resume after interruption.

The starter uses CPU mode, 4 threads and a 2048-token context as a conservative baseline. Performance and memory use vary by device temperature, available RAM and Android background restrictions. Keep Termux open while using the local model. No root access is required and the script does not delete user files.

Stop the API with Ctrl+C. To stop the model server separately, run:

    kill $(cat ~/.ayratma/llama-server.pid)

## API

- GET /health — backend health
- GET /model/status — checks whether the local model server responds
- POST /chat with a JSON message — real local model inference, specialist role prompt, recent chat context and saved-note context
- GET /agents and POST /agents — built-in and user-created specialist role profiles
- GET /tasks and POST /tasks/plan — task classification and plan records
- GET /memory and POST /memory — persistent notes
- GET /approvals and POST /approvals — approval records

The specialist agents share one model; they are not separate trained neural networks. Routing is deterministic, while the final answer is generated by the local LLM. Memory uses saved notes and a short recent chat window; it is not model retraining.

The model endpoint defaults to http://127.0.0.1:8080/v1/chat/completions. Only loopback endpoints are accepted. Do not expose the model server to the public internet.

## Honest limitations

This is a local assistant foundation, not a self-training autonomous superintelligence. It does not rewrite its own code, silently update itself, access protected Android app data, obtain root, or execute arbitrary shell commands. Evolution and cloud services remain future modules. Android may stop background work.
